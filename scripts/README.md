# scripts/ —— 仓库自身的检查 / 维护脚本

> 这里放**不参与产品**的脚本：只服务于"这个仓库本身"的健康度。
> 判断标准一句话：**它坏掉不影响 `local-mic`、也不影响 dsh 插件运行**。

## 什么该放这里

| 放 | 不放（该去哪） |
|---|---|
| 全仓级检查（断链、命名一致性……） | 产品代码 → `local-mic/`、`dsh-plugin/` |
| 仓库维护 / 一次性迁移辅助脚本 | 契约向量与夹具 → `conformance/` |
| 只读体检、报告类工具 | 诊断页与接缝工具 → `diagnostics/` |

**硬约束**：`scripts/` 下的文件**不得**被 `local-mic/`（csproj / C#）或 `dsh-plugin/` 引用 ——
一旦被引用，它就不再是"仓库维护脚本"，该挪进对应目录。

## 清单

| 脚本 | 干什么 | 跑法 |
|---|---|---|
| [`check-doc-links.mjs`](./check-doc-links.mjs) | 扫全仓 markdown 的**相对链接**报断链；已知但按约定暂不修的列在脚本内 `KNOWN_BROKEN`（带原因与日期，修好后脚本会反过来提醒删条目） | `node scripts/check-doc-links.mjs`（有问题退出码 1）；`--all` 连已知项一起列 |

## 约定

- Node ESM（`node ≥ 20`）、**零第三方依赖** —— clone 下来直接能跑。
- **只报告，不自动改文件**（改仓库的活留给人和 agent 审阅）。
- 退出码：`0` 干净、非 `0` 有问题（可直接串进 CI）。
- 新增脚本时**同时更新本文件的清单**（一行：干什么 + 跑法）。
