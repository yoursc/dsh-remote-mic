## 0. 先厘清职责边界（已定案的部分不重新论证）

```
浏览器（用户的 Windows）                        │  Host（N100 容器）
  dsh Web 页面                                  │
   └─ 我们的插件（dsh-plugin/，纯 client）        │
        ├─ 连 ws://127.0.0.1:8787 ─────────────┼─► 不经过隧道、不经过容器
        │   （local-mic 在 Windows 本机）        │
        ├─ 收 kind=0x02 + PCM16 载荷            │
        ├─ 组 WAV ──► remote.speech.transcribe()│──► SenseVoice（Host 侧推理）
        └─ insertText() 注入输入框              │
```

- 已定案（AGENTS.md §1）：**采集在 local-mic、转写在 Host、注入在 Client**（A1）；
  接缝词汇设备无关、插件不上行设备命令（A4）；插件 UI 只放一个图标、挂 `conversation.input.right`（DSH-SEAMS §7.2）。
- 因此**本文只讨论"还没定的"**：显示什么、在哪解析、怎么注入、边界与运维。

## 2. 逐条展开

### Q1 · 录音中（浮层关着）用户怎么知道"正在录"

- **现状**：图标 `data-rec="1"` 时外圈脉冲；浮层里显示「正在录音 x.x s」——但**浮层通常是关着的**。
- **候选**：① 图标脉冲（现状）；② 输入框旁内联一条细进度/波形；③ 提示音（开麦/收麦各一声）；
  ④ 接管输入框占位文案（"正在听…"）。
- **推荐**：① 保留 + ③（可选，需用户偏好）；②④ 会挤占输入框/干扰输入，暂不做（DSH-SEAMS §7.2 已定"只放图标"）。
- **坑**：任何"额外 UI"都要考虑与官方麦克风并存时的视觉噪音；v1.1 的实时波形属另一个量级的改动。

### Q2 · 错误的可见级别

- **现状**：`error` 只写进 `lastError`，要打开浮层才看得到；`retryable` 被丢弃。
- **候选**：① 保持（浮层内）；② 图标变红（**已实现**）+ 浮层；③ 一次性 Toast（`primitives` 里有 `Toast`）。
- **推荐**：②（已有）+ **连接级/被拒类错误用一次 Toast**（例如 `proto_mismatch`、`pairing_required`、连续重连失败）。
  注意协议 §7：`error.code` 值域开放，行为只能由 `retryable` 决定，**不要按 code 猜语义**。
- **坑**：Toast 是宿主级 UI，别做成"每次错误都弹"；要有去重与节流。

### Q3 · 音频在哪里"解析"（三层拆开看）

| 层 | 做什么 | 现在在哪 | 建议 |
|---|---|---|---|
| L1 | ADPCM → PCM16（设备编码） | `local-mic` | **不动**（定案 A3：设备适配全在 local-mic） |
| L2 | 帧头解析（1 字节 kind）+ 按字节累积 + 区间（start..end）判定 | 插件（已实现） | 留在插件（协议 §10 不变量 5/7 就是这么要求的） |
| L3 | 补 44 字节 WAV 头 | 插件（已实现，17 条断言） | **留在插件** |
| L4 | 电平/质量指标（峰值/RMS dBFS、削顶） | 未做 | **插件侧纯函数**（正是"喂 ASR 够不够"要测的那一层） |
| L5 | VAD / 切段（v1.1 实时转写的前置） | 未做 | 待 v1.1 定；**不要在 v1 提前做** |

- **候选（L3 的另一种走法）**：让 local-mic 直接发**文件字节**（WAV），插件不再封装。
  好处：多客户端复用、插件更薄；代价：**属破坏性接缝变更（要抬 `proto`）**，且让设备侧长出容器格式概念。
- **推荐**：保持现状。理由：接缝刚冻结，44 字节头是插件侧 30 行代码，不值得为此抬协议号。
- **坑**：未知 `kind` 必须忽略并只告警一次（已实现）；PCM16 载荷长度必须偶数（已实现）；
  **不要**在插件里做任何设备解码（会违反 A4）。

### Q4 · 电平测量（顺带解决 DEV.md 的 🟡 未验证项）

- **现状**：DEV.md 记着"遥控器原始电平约 −30.6 dBFS，直接喂 ASR 够不够**尚未实测**"，
  而"加增益"属破坏性变更（要抬 proto）——所以**先量清楚**再谈增益。
- **做法**：对收到的 PCM16 直接算峰值 / RMS（dBFS）+ 是否削顶（`|sample| >= 32767`），浮层显示一行。
- **推荐**：做，且这是"先打磨采集端"里性价比最高的一件（不需要 ASR、不需要你反复试听）。
- **坑**：测的是"接缝交付给 ASR 的那份音频"，若 local-mic 侧已有增益，这里量到的是增益后的值——
  这正是要记录的语义，别把它当成"遥控器原始电平"。

### Q5 · 转写 seam 与部署（第②步的前置）

- **已核实的事实（2026-10-02）**：
  - 客户端模块图里**没有任何 speech/voice 行**；profile 的 `node_modules` 里也没有 speech 包
    ⇒ **本机 `remote.speech` 不存在**。DSH-SEAMS §7.1 那句"已被官方 bundle 挂好"是在 **desktop** profile 上取的证。
  - `~/.dsh/speech-to-text/sensevoice/models/` **不存在** ⇒ 本机没有 SenseVoice 模型（228 MB）。
- **候选**：
  a. 给 web profile 装 `@deepseek-ai/dsh-experimental-voice-input-bundle` + 准备模型 ⇒ 走定案 A1。
     副作用：官方麦克风 UI 一并出现（已论证两个入口语义不同、可共存）。
  b. 插件自己 `$mount` speech contribution（要写 Host 部分、引入 speech 包）⇒ 与 §7.1"只消费"相悖。
  c. 换转写路径 ⇒ 与 A1 冲突，须重新论证。
- **推荐**：a；但**先确认模型从哪来**（是否有官方下载入口/文档；容器内需网络与磁盘）。
- **坑**：装完必须验 `remote.speech` 真出现在客户端模块图；ASR 未就绪要在**开口之前**提示
  （用 §7.4 的 `follow()` 订阅，而不是说完话才报错）；注意 `maxDurationSeconds` 是 ASR 的限制，
  **与设备 ~5.7 s 音频窗口不是一回事**，别混。

### Q6 · 文字怎么进输入框

- **官方语义（DSH-SEAMS §2，实证自 voice-input）**：
  `span = inputActions.captureInsertion()`（**开始录音时取**）→ `insertText(text, span)` →
  失败则 `setPending(text)` + 可见提示；**重试时必须重新取快照**。
- **待定**：① 我们的槽组件如何拿到 `inputActions`（需照官方 voice-input 的 inject 写法确认）；
  ② 是否有"复核再注入"的交互；③ pending 重试入口放哪（浮层里 / Toast）。
- **推荐**：完全照抄官方语义，不发明新交互；注入成功给轻反馈即可（见 Q7）。
- **坑**：`insertText` 有版本校验（会话/选区变了就拒）⇒ **绝不能丢字**；v1 **不自动发送**（定案 A8）。

### Q7 · 注入成功的反馈

- **候选**：① 什么都不做；② 图标短暂变绿/打勾；③ 输入框内联提示；④ Toast。
- **推荐**：②（侵入最小）；失败时用 ③ 或浮层内提示（与 Q6 的 pending 一致）。

### Q8 · F5 / Ctrl+R 拦截（**存在一个未解释的现象，必须先取证**）

- **文档要求**：HARDWARE §4.1.1「语音键 = F5 = 浏览器刷新页面……**写 dsh 插件时必须带上这个拦截，否则一按就刷新**」。
- **现状**：**当前插件没有实现任何 F5 拦截**；而 2026-10-02 用户实机按住语音键录音 + 试听**正常工作、未观察到页面刷新**。
- **⇒ 现象与文档记录不符，先取证再改**（三个待查点：F5 是否真的送到页面；是否被输入框/宿主快捷键吃掉；
  当时遥控器是否以 HID 键盘方式活动）。取证手段：在页面里挂一个临时 keydown 记录（写 `sessionStorage`，
  页面重载也能看到前一次的记录——PITFALLS #19 就是这么干的）。
- **若确认需要拦截**：按 DSH-SEAMS §7.5 的定案——**只在接缝就绪时接管**，平时交还，并在浮层里明说"已接管"；
  同时告知用户"想刷新请用 Ctrl+F5"。
- **坑**：全局拦截 = 用户无法刷新页面；`preventDefault` 要同时覆盖 `F5` / `Ctrl+R` / `BrowserRefresh`。

### Q9 · 连接生命周期与多标签页

- **现状**：模块级单例连接；重连指数退避 500 ms → 8 s；**没有 `ready` 超时**（若对端接受连接但从不发 `ready`，
  会一直停在"连接中"）；端口存浏览器 `localStorage`。
- **待定**：① local-mic 的 WS **是否允许同机多客户端**（两个标签页/诊断页同时连）——仓库文档里没写，
  需查 local-mic 源码（Windows 侧）；② 若不允许：用 `BroadcastChannel` 选主（只有 leader 连）还是明说"单标签"；
  ③ `ready` 超时时长与提示。
- **推荐**：② 先查清事实再定；③ 加 8 s 超时 + 明确文案（诊断页踩过"超时判定过早"的坑，见 PITFALLS #29）。
- **坑**：僵尸连接会导致双份音频订阅（DSH-SEAMS §3.1 提过）；切换端口时必须先收尸再连。

### Q10 · 性能与上限

- **现状**：`onBinary` **每帧 emit**（15 ms 一帧 ⇒ 约 66 次/秒），每次都 `Object.assign` 新快照并通知订阅者
  ⇒ 组件高频重渲染（按住约 5.7 s 一段 ≈ 380 次）。
- **推荐**：UI 进度类字段（字节数/时长）**节流**（例如 ≥100 ms 或整 KB 变化才 emit）；
  **音频累积本身绝不节流**（丢帧就是丢音频）。
- **坑**：节流写错位置会变成丢数据；`lastClip` 只在收段时更新，避免大对象频繁进 state。

### Q11 · 多外设解耦（与 DEV.md 待办 2 同源，这里只列插件侧要做的事）

- 插件侧需要预留的抽象：**输入源标识**（显示名/来源标注）、**能力描述**（是否按住型 / 典型时长 /
  是否带电平），以及"文案与图标可替换"（别把"遥控器"写死在代码里）。
- **`capture.source` 现在完全没消费**——协议已定义且明确"仅用于 UI 标注、不得参与逻辑分支"，这是**零协议成本**的一步。
- **能力描述若落在接缝上 ⇒ 必须先改 `PROTOCOL.md` 并论证是"非破坏性扩展"还是"抬 proto"**（纪律 §4）。
- **坑**：参考 DEV.md 待办 2 的三条坑（别过度设计、别用 `source` 冒充能力、任何字段新增都走规范先行）。

### Q12 · 可测试性与回归

- **已有**：`pcmToWav` 纯函数断言 17 条；无浏览器**接线测试** 15 条（能抓到本次那类"状态未解构"bug：
  对原始提交版本 FAIL ①②）。
- **待定**：接线测试是否入库（当前用户选"暂不入库"）；接缝→UI 的回归怎么覆盖（现在只有"服务端取回真实产物再跑测试"这一步）。
- **推荐**：至少把脚本存档（放 `dsh-plugin/test/` 或 `diagnostics/`），并在纪律里写明"改接线必须跑"。

### Q13 · 分发与隐私

- **分发**：现在 `private: true` + `link:` 装机，只适合本机迭代；要给别人用需要
  改 `package.json`（去掉 private、写 README、声明 dsh 兼容范围）+ `dsh plugin add <包名>`。
- **隐私**：音频**离开本机**进容器做 ASR（定案 A1 的必然结果），应在 README/首次使用时说清；
  目前插件没有做任何持久化，音频只存在于内存（`lastClip`）。

## 3. 已发现、与设计无关但应当先补的缺口（事实性）

| # | 缺口 | 依据 | 影响 |
|---|---|---|---|
| G1 | **没有 F5/Ctrl+R 拦截** | HARDWARE §4.1.1 明确要求 | 可能一按语音键就刷新页面（现象与记录不符，见 Q8） |

| G6 | 旧错误不会在恢复后清除 | 代码实测 | 浮层长期显示过期错误 |

## 4. 建议的定调顺序（等你回来，一次只定一个）

1. **Q8 先取证**（今天就能做，且涉及"会不会突然刷新页面"这种阻塞性风险）；
2. **Q5 转写前置**（决定第②步能不能开始，也决定要不要现在下载 228 MB 模型）；
3. **Q4 + Q3**（打磨采集端：电平 + WAV 留在插件的确认）；
4. **Q2 + Q1 + Q7**（UI 表达：错误、录音中、注入反馈）；
5. **Q6 + Q9 + Q10**（注入语义 + 生命周期 + 性能）；
6. **Q11 + Q13**（解耦与分发，与 DEV.md 待办 2 合并推进）；
7. **Q12**（测试是否入库）。
