# notes/ —— 中间态过程稿（不作为结论来源）

> 这里放**开发过程中的临时文件**：调研、修改意见、设计草案、评审快照、方案书。
> 它们的共同点：**结论一旦落定就搬进长期文档**，文件本身只留作追溯。

## 规矩（三条）

1. **结论落在长期文档**：`../PROTOCOL.md` / `../HARDWARE.md` / `../DSH-SEAMS.md` / `../PITFALLS.md` /
   `../REFERENCES.md` / `../../AGENTS.md` / `../../DEV.md`。**本目录不是真源。**
2. **每份文件头部必须有状态块**，且**已落定必填落点**（模板见下）。
3. **冲突时以落点文档为准**；未登记落点的过程稿，**不得被引用为结论**。

## 头部状态块（照着抄）

```markdown
> **状态**：📝 待落定 ｜ ✅ 已落定 ｜ 🗑 已废弃
> **落点**：`../X.md` §Y（已落定必填）
> **日期**：YYYY-MM-DD · **作者**：agent / 人名
>
> 过程稿：**不作为结论来源**；与落点文档冲突时，以落点文档为准。
```

| 状态 | 含义 | 该做什么 |
|---|---|---|
| 📝 待落定 | 结论 / 待办还没进长期文档 | 拍板后把结论写进长期文档，回来把状态改成已落定并填落点 |
| ✅ 已落定 | 结论已进长期文档，这里只剩追溯价值 | 只增不改；引用时请引落点文档 |
| 🗑 已废弃 | 被其它文档 / 方案取代 | 头部写明被谁取代 |

## 命名

`<主题>-<类型>-<日期>.md`，类型 ∈ {调研, 修改意见, 评审, 方案, 历史推演}，日期用 `YYYY-MM-DD`
（取内容里的"调研 / 评审时间"，不是文件创建时间）。
